Define Documentation Structure

Brief

The article describes the group definition and behavior

Details

There are four tags that define the structural elements of the documentation:

1) Groups.

Groups is the key element of the organization of the documentation structure. All groups are organized in a tree. One group is always a root (index) group. All other elements (groups, articles, classes) must belong to one of groups.

2) Articles

Articles are intended to provide a plain text explanation which does not have any sub-levels and is not connected to the programming code.

3) Classes

Classes are intended to provide documentation of code-related things. While they are called "classes" they may represent many different constructors: classes themselves, SQL tables, XML schemas, sets of functions for non-OOP languages and many others.

Groups, Articles and Classes are only three documentation objects that may appear on the top level. All other elements must be used inside one of these objects.

These three objects must clearly define to which group they are belong to. There is only one exception - an index group which does not belong to any other groups. This group makes the root of the documentation content tree and is displayed first.

4) Members

Members is another level of hierarchy that defines one element of a class. An examples of members could be fields, methods, properties, functions, tags, table columns. Members are always used inside of a class.

Each element of the structure has an unique key. The key must be unique among ALL documentation objects. The key is used to refer the element in contents or in link bbcode tags.

The key of members typically automatically include the key of the class that contains the member (unless it is directly disabled in the class properties).
