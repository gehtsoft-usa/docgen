HTML template

Brief

The section describes the template that creates HTML based documentation from the source files

Details

The template is used to create the HTML documentation for WEB publishing as well as to be compiled using HTML Help Compiler.

The template is located at %docgen%/template/html/main.xsl

This template creates multiple output files, so use file parameter of the output element of the project file to specify the destination folder:

Example:

<dg:output template="%docgen%/template/html/main.xsl" file="dst/null-file" encoding="utf-8">

The template has the following parameters. All parameters are optional and are set using dg:define elements inside the output element of the project file.

General

Parameter

Description

text-language

2-letter language code, e.g. en.

The parameter is used to localize the output documentation. en, fr and ru are supported.

If the parameter is not set, the default language of the template dictionary (en) is used.

help-title

The title of the help.

The value is used as the title of the container page, in the header of the container page, and as the title of the HTML Help project.

default-transform

yes or no

The flag indicating whether the compiler must escape HTML character and process bbcodes.

The option is mostly used for backward compatibly with very old sources that has been created before bbcodes are introduced.

enable-highlighter

yes or no, default is no

The flag indicating whether a syntax highlighting must be enabled for the samples.

Highligh JS is used for highlight the syntax.

add-signature-to-brief

yes or no

The flag indicating whether the parameters needs to be added to the name of the methods and to constructors in the member lists. The option is useful for libraries with a lot of overrides. See also @class/@writeSignatures property.

create-group-for-members-with-same-name

yes or no, default is no

When the model has multiple methods with the same name, an additional topic with they equal to the name of the class and name of the method group is created.

Web Container and Content Tree

Parameter

Description

write-web

yes or no, default is yes

The flag indicating whether the files of the web container (the frame page and the content tree page) must be created.

Set the value to no if the output is intended to be compiled into a CHM file only. In this case only the topic files and HTML Help project files are created.

advanced-web-content

yes or no, default is no

The flag indicating whether the content tree must be interactive (e.g. you can collapse nodes)

web-content-file-name

The name of the file of the web container page, without the extension. The default value is web-content, so the container page is named web-content.html.

Use the parameter in the environments where the name of the default file cannot be changed, e.g. in github pages set the value to index. See Adding Custom Content for the details.

The parameter has no effect if write-web is set to no.

web-content-file-name-backward-compatibility

yes or no, default is no

If the value is yes, the container page is additionally written into web-content.html even when web-content-file-name re-defines its name.

Use the parameter to keep the old links working after the name of the container page is changed.

Appearance and Custom Content

All file names below are resolved first against the current folder (i.e. the folder from which the compiler is started) and then against the folder of the template. The content of the file is inserted into the output as is, without any processing.

Parameter

Description

external-resources

yes or no, default is no

If the value is yes the scripts and css are loaded from res/scripts.js and res/styles.js file.

The default implementation would be copied during the compilation, but you can redefine the styles and scripts behavior.

add-custom-script

The relative file name or URL for a script to be added

add-custom-style

The relative file name or URL for a custom stylesheet to be added

add-to-prolog-head

The name of the file with an HTML fragment to be inserted into the head tag of every topic page (articles, groups and members), right before the closing /head tag.

Use the parameter to add meta tags, analytics counters, a favicon reference, or additional style and script links.

add-to-prolog-body

The name of the file with an HTML fragment to be inserted into every topic page right after the opening body tag.

Use the parameter to add a custom header banner.

add-to-epilog

The name of the file with an HTML fragment to be inserted into every topic page right before the closing /body tag.

Use the parameter to add a custom footer.

add-to-container-prolog-head

The name of the file with an HTML fragment to be inserted into the head tag of the web container (frame) page.

Note that the topic pages are not affected by this parameter, use add-to-prolog-head for them.

replace-container-prolog-title

The name of the file with an HTML fragment that replaces the table cell (the whole td tag must be included into the fragment) that contains the header text of the web container page.

If the parameter is not set, the cell with the value of help-title in bold is written.

HTML Help (CHM)

Parameter

Description

write-hhp

yes or no, default is yes

If value is "yes" an HHP project file will be created.

You can call HTML Help Compiler 1.3 or 1.4 to create a CHM file.

The flag indicating whether HTML Help project needs to be generated

hhp-language

The full name of the language, e.g. 0x409 English (United States)

The parameter is used to generate HTML Help project file

hhp-codepage

The encoding of the generated HTML Help project file, e.g. windows-1251. The default value is windows-1252.

HTML Help Compiler does not support UTF-8 project files, so use the ANSI code page that matches the language of the documentation.

chm-file

The name of the CHM file to be created.

The parameter is used to generate HTML Help project file

Overriding the Localized Labels

The template writes the fixed labels of the topics (Brief, Details, Parameters and so on) using the values from the dictionary %docgen%/template/html/dictionary/translation.xml.

Any of these labels can be overridden without modifying the template by defining a parameter named _string_ followed by the identifier of the string, for example:

<dg:define name="_string_seealso" value="Related Topics" />

The following identifiers are defined: brief, details, back, declaredin, declaration, return, exceptions, parameters, seealso, parents, articles, groups, and index.

A parameter defined in the project file takes precedence over the value from the dictionary, no matter which text-language is set.
