Special Case: Class defined in multiple files

Brief

The article describes how docgen handles classes declared in multiple files

Details

While in most cases the content of one documentation object is defined in one text file, the class content may be split between multiple files.

When the class with the same key is defined multiple times, the following rules apply:

1) The values for all attributes will be taken from the first occurrence of the class. The values from the other occurrences will be ignored.

2) The members of the all next occurrences will be added to the class, unless they are defined earlier. The second definition of a member with the same key will be ignored.

This feature is useful in two specific cases:

1) A class with large number of methods may be separated to multiple files for simpler modification and handling.

2) If documentation is partially generated from the source code, the following trick may be used:

2.1) Put auto-generated code to the very end of the source list in the documentation project file. So, auto-generated documentation will be used only in case when it is not manually refined.

2.2) To refine auto-generated description, create a class definition with the same key and put it before auto-generated documentation in the source list in the project file.

2.3) Define only methods you want to refine. The rest of the methods will be taken from the auto-generated part.
